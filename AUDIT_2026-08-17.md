Полный аудит четырьмя проходами: речевая подсистема, текстовый конвейер, UI-слой, Silero-сервер.
Почти все находки проверены чтением реального кода; помеченные «ДОКАЗАНО» — воспроизведены
исполняемыми харнессами (компиляция реальных файлов `Core/` + ассерты) или замерами.
Уже отложенные по прошлому аудиту A1/A2 (шов SpeechBackend, God-объект ReaderViewModel)

## КРИТИЧНО — фиксить первыми

### К1. Краш «Index out of range» на юникод-числах (ДОКАЗАНО, воспроизведён)
`Core/RussianProfile.swift:299-303, 319-323, 437-442`

`expandNumbers` считает цифрой любой `Character.isNumber` (включая Nl/No: римские Ⅻ, кружковые ⑩),
а per-digit ветка делает `nDigit[$0.wholeNumberValue]` — для Ⅻ это `nDigit[12]` → фатальный выход
за границы массива из 10 элементов. Книга с «Часть Ⅻ» или «⑩» падает, как только чтение доходит
до этого места (render идёт при воспроизведении, AVSpeech наполняет окно на 50 предложений вперёд).
Позиция сохраняется → повторное открытие падает снова: **книга становится непроигрываемой**.
Побочно: «½», «¼» молча выпадают из речи (`wholeNumberValue == nil` → пустая строка).

**Фикс (3 строки):** в `expandNumbers` сканировать только ASCII-цифры (`ch.isASCII && ch.isNumber`);
в обеих per-digit ветках `compactMap { (0...9).contains($0) ? nDigit[$0] : nil }`.

`PDFVoice/Settings/SettingsStore.swift:50` — `let sileroAPIKey = "n8tJ…"`

Репозиторий публичный (проверено `gh repo view` → `"visibility":"PUBLIC"`), ключ в рабочем дереве

**Фикс:**

   `.xcconfig`/env (XcodeGen умеет), файл в `.gitignore`; историю почистить `git filter-repo`.
3. Проверить в панели Cloudflare, что WAF rate-limit из `DEPLOY.md:205-207` реально создан —
   он нигде не зафиксирован кодом.
4. Записать в `DEPLOY.md` процедуру ротации (старые установки получат 401 → мягкий откат
   на системный голос — проверено, деградация корректная).

### К3. Retain cycle: `SpeechEngine` не освобождается никогда (ДОКАЗАНО)
`Core/SpeechEngine.swift:195, 204, 233` → `AVSpeechBackend.swift:34,58`, `SileroBackend.swift:35,90`

`active.play(..., render: render(_:))` передаёт метод-референс с сильным захватом `self`;
backend хранит его в `currentRender` и не обнуляет. Цикл `SpeechEngine → backend → currentRender →
SpeechEngine`. Харнесс: `play+stop → LEAK`. Каждая проигранная книга утекает целиком
(sentences + копии в обоих backend'ах + синтезатор + наблюдатели NotificationCenter, deinit
не вызывается). 15 книг за сессию → десятки МБ и риск jetsam.

**Фикс:** замыкание `{ [weak self] s in self?.render(s) ?? … }` вместо метод-референса +
обнулять `currentRender` в `stop()` обоих backend'ов.

### К4. Предложение-ссылка роняет нейроголос на Милену до конца сессии (ДОКАЗАНО)
`Core/SpeechEngine.swift:287-292` → `SileroBackend.swift:171-199` → `silero-server/server.py:94`

`render` для пустого после раскрытия предложения (URL целиком вырезается `stripLinks`) возвращает
`" "` → Silero POST'ит пробел → сервер отвечает 400 → клиент ретраит только 5xx → `.failed` →
`fallBackToSystemVoice`. Любая сноска-ссылка молча переключает книгу на системный голос.

**Фикс:** (1) пустой markup — не делать сетевой запрос, эмитить `didStart` и выдержать паузу;
(2) в `fetchAudio` различать 4xx (пропустить предложение) и сеть/5xx (настоящий откат).

### К5. Потеря сохранённой позиции чтения на больших книгах
`Reader/ReaderViewModel.swift:431-434, 507-509, 691-694, 864`; `Library/DocumentStore.swift:49-54`

`SpeechEngine.load` клампит сохранённый индекс по загруженному префиксу (первые 15 страниц).
Нажал ▶ до конца фоновой загрузки → чтение стартует с ~299 вместо 5000, `onIndexChange` тут же
**затирает 5000 на диске**, а финальный `seekSilent` пропускается из-за гарда `!speech.isSpeaking`.
Проверки восстановления на `:431-434` и `:691-694` мертвы по построению (условия несовместимы).
Чисто-OCR путь (`runOCR`) не восстанавливает позицию вообще.

**Фикс:** `pendingRestoreIndex: Int?` — досеивать после каждого `appendSentences` во всех трёх
путях; пока он не nil — не персистить меньшие индексы; сбрасывать при явном действии пользователя.

### К6. Ложное «Прочитано» и остановка озвучки на границе догруженного префикса
`Core/AVSpeechBackend.swift:166`, `SileroBackend.swift:161`, `SpeechEngine.swift:221-244, 257`,
`Reader/ReaderViewModel.swift:87-90`, `Reader/MiniPlayerView.swift:42`

Кластер из четырёх путей к одному дефекту — backend'ы считают концом книги конец *загруженного*
массива:
- Догнал загрузку (skip до конца префикса, короткий первый батч) → `.finishedAll` →
  `markFinished` (галочка «Прочитано» на 3% книги) + очередь встала, догруженные батчи
  воспроизведение не перезапускают.
- `resume()` на пустой очереди (▶ в мини-плеере, пока идёт OCR — кнопка не гейтится) →
  мгновенный `.finishedAll` (ДОКАЗАНО харнессом).
- `skipForward` на последнем предложении клампится в тот же индекс → перечитывание + `finishedAll`.
- Признак `isLoadingRemainingPages` уже существует (`ReaderViewModel.swift:14`), но не читается никем.

**Фикс:** флаг «книга загружена целиком» в `SpeechEngine` (выставляет ReaderViewModel);
при `finishedAll` и незавершённой загрузке — не звать `onFinishedAll`, остаться в «голодном»
состоянии, из которого `appendSentences` перезапускает очередь. Плюс `guard !sentences.isEmpty`
в `resume()`, гейт кнопки мини-плеера, guard в `skipForward`.

### К7. Фоновая загрузка не отменяется при закрытии/смене книги + retain cycle задачи
`Reader/ReaderViewModel.swift:879-885 (endSession), :445, :543, :705, :310`; `Core/PlaybackCoordinator.swift:24-44`

`endSession()` не делает `backgroundTask?.cancel()`, `deinit` отсутствует, Task держит `self`
сильно. Следствия: закрыл 700-страничный скан → OCR продолжает жечь CPU/батарею до конца;
удалил книгу → живой таск пересоздаёт кэш удалённой книги (осиротевший файл); зомби-`SpeechEngine`
старой сессии остаётся подписан на прерывания аудиосессии и после звонка может начать читать
**старую книгу поверх новой**. `loadReflow` свой Task вообще не сохраняет. Смежно: `speech.stop()`
не вызывается нигде в проекте, аудиосессия никогда не деактивируется (чужая музыка не
возобновляется после закрытия плеера).

**Фикс:** `backgroundTask?.cancel()` в начале `endSession()`; сохранить Task из `loadReflow`;
проверять отмену до `SentencePageCache.save`; `[weak self]` в телах Task; в `endSession` —
`speech.stop()` + `setActive(false, options: .notifyOthersOnDeactivation)` + отписка от нотификаций.

## СЕРЬЁЗНО

### Silero-сервер (защита собственного прода)

- **С1. Ошибка синтеза → `200 OK` + 0.12 с тишины** (`server.py:84-87`). Offline-fallback на этом
  пути не срабатывает никогда: подсветка идёт, звука нет, ошибок нигде. Фикс: реальные исключения →
  `503` (клиент ретраит 5xx и корректно откатывается на Милену); тишину оставить только для
  «текста без букв».
- **С2. Нет лимита длины текста и тела запроса** (`server.py:90-99`). Клиент тоже не режет
  предложения (страница без пунктуации = одно «предложение» на тысячи символов; у `apply_tts` есть
  лимит → тишина, см. С1). POST на 100 МБ → OOM на 4 ГБ машине. Фикс: `Field(max_length=800)` +
  middleware по `Content-Length` (~64 КБ) + на клиенте резать предложения > ~600-700 символов
  по пунктуации (полезно и для AVSpeech).
- **С3. Лавина под нагрузкой** (`server.py:18` + `SileroBackend.swift:187-206`). Неограниченная
  очередь executor'а + клиентские ретраи по таймауту: латентность > 30 с → каждый клиент шлёт ×3.
  Отменённые клиентом клипы сервер всё равно синтезирует. Фикс: семафор ожидающих → `503` при
  переполнении; `await request.is_disconnected()` перед executor; `asyncio.wait_for` ~20 с.
- **С4. Пустой `SILERO_API_KEY` → сервер молча открыт** (`server.py:30-41`). Fail-open + warning
  в буферизованный stdout. Фикс: `SystemExit` при пустом ключе без явного `SILERO_ALLOW_ANON=1`.
- **С5. `rsync` деплоя не исключает `.env`/`.api_key`** (`DEPLOY.md:226-230`, `README.md:14-18`) —
  локальные файлы перезапишут прод-конфиг. Фикс: `--exclude='.env' --exclude='.api_key' --exclude='.git'`
  + `chown` после rsync.
- **С6. Гонка torch.hub при первом старте с `WORKERS≥2`** (`server.py:44-50` + `silero.service:13`).
  Spawn-воркеры без блокировок качают/распаковывают в один каталог → рестарт-луп с
  `FileNotFoundError`/`BadZipFile`. Фикс: шаг прогрева одним процессом в `DEPLOY.md`
  (или `fcntl.flock` вокруг `torch.hub.load`).

### Речевой движок

- **Р1. Прерывание возобновляет то, что пользователь паузил вручную** (`SpeechEngine.swift:169-182`).
  Пауза → звонок → `.ended(.shouldResume)` → книга сама начинает читать (в кармане, ночью).
  Фикс: флаг `pausedByInterruption`, возобновлять только по нему.
- **Р2. Нет реакции на смену аудио-маршрута** (`SpeechEngine.swift:100-113`). Выдернул наушники —
  книга орёт из динамика. Фикс: `routeChangeNotification` + `.oldDeviceUnavailable` → `pause()`.
- **Р3. Смена скорости на паузе игнорируется целиком** (`SpeechEngine.swift:39-44` —
  guard `isSpeaking`). Пауза → поменял скорость → плей — скорость старая до ближайшего skip.
  Фикс: всегда прокидывать `setSpeed` и синхронизировать `currentSpeed` в обоих backend'ах.
- **Р4. `resume()` ветвится по конфигу, а не по фактическому backend'у** (`SpeechEngine.swift:226`).
  После отката на Милену `sileroServerURL != nil` → Silero-ветка → перечитывание предложения
  с начала. Фикс: ветвиться по `active === sileroBackend`.
- **Р5. Silero: смена скорости посреди клипа ломает расписание** (`SileroBackend.swift:80-84` vs
  `:224-235`). `Task.sleep` посчитан один раз от старой скорости: ускорил → секунды тишины;
  замедлил → обрыв фразы на полуслове. Фикс: планирование по дедлайну с пересчётом в `setSpeed`,
  а лучше `AVAudioPlayerDelegate` вместо sleep.
- **Р6. Silero: `didStart(i)` эмитится до получения аудио** (`SileroBackend.swift:132-133`).
  Подсветка/прогресс уезжают на непрозвучавшее предложение; пауза в этот момент может
  **пропустить предложение** при resume. Фикс: перенести `queueIndex = i` + `didStart` вплотную
  к `playAndWait`.
- **Р7. До ~90 с тишины перед откатом при недоступном сервере** (`SileroBackend.swift:176, 187-206`:
  30 с × 3 + бэкофф; iOS в фоне убьёт приложение на такой тишине). Фикс: таймаут 8-10 с,
  максимум 2 попытки; перед включением Silero — быстрый `/health`-проб (как в `probeSilero`, 4 с).
- **Р8. Префетч не отменяется, клипы не кэшируются** (`SileroBackend.swift:114-123, 46-52`).
  `Task.detached` живёт после pause/stop; каждый pause→resume и skipBackward перекачивает то же
  аудио. Фикс: хранить `pending` в свойстве + cancel; LRU-кэш `Data` на 20-30 клипов.
- **Р9. Сетевой путь Silero изолирован на MainActor** (`SileroBackend.swift:171`). JSON-энкод,
  сборка WAV-Data, `AVAudioPlayer(data:)+prepareToPlay` — всё на main каждые ~5 с. Фикс:
  `nonisolated fetchAudio` с локальными копиями конфига.

### Производительность / main thread (UI + конвейер)

- **П1. Классификация ВСЕХ страниц синхронно на main при каждом открытии**
  (`ReaderViewModel.swift:205-215`). Замер: ~3.3 мс/страница на Mac → **1-1.5 с фриза на
  156-страничной книге, 4-8 с на 700-страничной на устройстве**, даже у полностью закэшированных
  (проверка кэша стоит ПОСЛЕ классификации). Фикс: сперва проверять кэш (при `isComplete`
  классификация не нужна), остальное — в `Task.detached`; плотность считать по префиксу ~400
  значимых символов, не по всей странице.
- **П2. `SentencePageCache.save` на main в OCR-цикле — O(n²)** (`ReaderViewModel.swift:588, 627`,
  тогда как соседние пути обёрнуты в `Task.detached`). Замер: к концу большой книги 150-200 мс
  залипания на каждый батч из 15 страниц, ~47 сохранений на 700-страничном скане. Фикс:
  `Task.detached(priority: .background)` + дебаунс.
- **П3. `VoiceCatalog.options()` в `body` читалки** (`ReaderView.swift:165-182`,
  `VoiceCatalog.swift:30-39`). `AVSpeechSynthesisVoice.speechVoices()` + filter + sort вызываются
  на КАЖДЫЙ пере-рендер — то есть десятки раз в секунду при скролле reflow. Фикс: статический кэш
  в `VoiceCatalog` + `@State` в `ReaderScreen`.
- **П4. Reflow: репорт скролла без дедупликации** (`ReflowReaderView.swift:513-527, 545-549`;
  `ReaderView.swift:402-414`). Каждый кадр прокрутки → `closestPosition` + `glyphRange` + четыре
  присваивания `@State` (одно под `withAnimation`) → полный пере-рендер `ReaderScreen` (включая П3).
  Джиттер на больших EPUB/FB2. В PDF-пути дедуп уже есть (`PDFKitView.swift:427-442`) — перенести
  тот же паттерн.
- **П5. `store.save()` (JSON всей библиотеки + атомарная запись) на каждое предложение**
  (`DocumentStore.swift:49-54` из `onIndexChange`), плюс публикация `items` → пере-рендер
  `LibraryView` под читалкой каждые 2-5 с. Фикс: дебаунс 5-10 с + принудительно на
  `endSession`/`background`; запись off-main; `lastOpened` — один раз при открытии.
- **П6. PDF: `page.selection(for:)` на каждом тике скролла** (`PDFKitView.swift:258-299`).
  Фикс: кэшировать rect подсветки в координатах страницы по `sentence.id`, на тике — только convert.
- **П7. Общий `PDFDocument` читается с фоновых потоков параллельно с main** (подозреваемое;
  `ReaderViewModel.swift:447-456, 797-799`; `OCRTextExtractor.swift:39-41, 91, 217` vs `revealPages`
  на main). PDFKit не thread-safe; проект сам решил это в `ThumbnailGridView.swift:146` отдельной
  копией — пути извлечения правило не соблюдают. Возможный источник редких крашей. Фикс: вторая
  копия `PDFDocument(url:)` для всех фоновых путей. Подтвердить: TSan + скролл при дозагрузке.
- **П8. Неограниченный кэш миниатюр** (`ThumbnailGridView.swift:141`) — словарь без вытеснения,
  700 страниц накапливаются все; рядом в `BookCoverView` уже используется `NSCache`. Фикс:
  `NSCache` с `countLimit≈120`; открытие копии документа — лениво off-main.
- **П9. Reflow-книги переразбираются целиком при каждом открытии** (`ReaderViewModel.swift:302-342`
  — кэш не используется). Фикс: кэшировать предложения + `flatText`/`chapterOffsets`
  (сперва добавить `charOffset` в `EncodedSentence` — см. М14).

### Качество озвучки (текстовый конвейер)

- **Т1. Аббревиатуры без границ слова** (`RussianProfile.swift:142-144`): «Это был Борис.» →
  «Это был Борисунок» (ДОКАЗАНО; «рис.» внутри «Борис.», аналогично «гл.», «см.»). Фикс: одна
  скомпилированная регулярка с lookbehind `(?<![\p{L}])` вместо 17 проходов `replacingOccurrences`.
- **Т2. Единица перед точкой конца предложения** (`RussianProfile.swift:180-186`): «Длина 5 см.» →
  «Длина пять смотри» (ДОКАЗАНО); «3 км.» вообще не раскрывается. Фикс: разрешить в lookahead
  точку перед концом строки/заглавной; «см.»→«смотри» только когда слева не цифра.
- **Т3. EPUB: `<head>`/`<style>`/`<script>` не вырезаются на многострочной разметке**
  (`EPUBSource.swift:126-129` — нет `.dotMatchesLineSeparators`, который в `firstHeading:132`
  уже стоит). Проверено на реальной книге: **в начале каждой из 45 глав читается
  «Crime and Punishment | Project Gutenberg»**; инлайновый CSS попадает в текст; мусор смещает
  детект языка. Фикс: один флаг.
- **Т4. OCR-боксы игнорируют поворот страницы и origin mediaBox** (`OCRTextExtractor.swift:59-65,
  178-184`; ДОКАЗАНО поведением PDFKit: thumbnail — повёрнутый, bounds — нет). На сканах с
  `/Rotate 90` подсветка полностью мимо, тап по предложению промахивается. Фикс: прибавлять
  `pageRect.origin`, при `rotation != 0` пересчитывать координаты Vision.
- **Т5. Текстовый путь не использует оконный детект колонтитулов** (`detectBoilerplateWindowed`
  зовётся только из OCR; текстовый путь — плоский `detectBoilerplate` с порогом, который в
  CLAUDE.md описан как провальный). Плюс колонтитулы считаются трижды по разным выборкам →
  нестабильный результат между страницами и сессиями. Фикс: windowed везде + объединение наборов.
- **Т6. `runOCR` не пропускает пустые страницы** (`isBlankPage` есть только в смешанном пути) —
  на чистом скане каждая пустая страница-разделитель проходит полный Vision-проход (0.5-1.5 с).
  Фикс: общий хелпер для обоих путей.

- **У2. Двойной рестарт предложения при смене голоса** (`ReaderViewModel.swift:99-131` +

## СРЕДНЕ / МЕЛОЧИ

- **М1.** `revealPages`: при неудаче `page.copy()` `loadedPageCount` уходит вперёд `displayDocument`
  → молчаливая деградация подсветки (`ReaderViewModel.swift:180-188`). Откатывать счётчик.
- **М2.** `mergeCrossPage` теряет `language`/`charOffset` (`PDFTextExtractor.swift:121-125`) —
  латентно до посегментного выбора голоса.
- **М3.** `decodeEntities`: недетерминированный порядок замен из Dictionary — `&amp;lt;` может
  превратиться в `<` (`EPUBSource.swift:146-150`). Массив пар, `&amp;` последним.
- **М4.** FB2 `<empty-line/>` создаёт пустые абзацы — то, от чего в EPUB/DOCX сознательно ушли
  (`FB2Source.swift:57-58`).
- **М5.** OCR-боксы захватывают выброшенные junk-строки внутри предложения
  (`OCRTextExtractor.swift:143-144`).
- **М6.** `isJunkLine`: 10 регулярок на каждую строку книги без префильтра (`TextPipeline.swift:102-120`).
- **М7.** `expandUnits` — 5 копий NSMutableString на предложение без цифр (`RussianProfile.swift:188-213`);
  дешёвый ранний выход.
- **М8.** EPUB: spine без фильтра `linear="no"`; декодирование только UTF-8 (`EPUBSource.swift:26-33`).
- **М9.** `SileroBackend.append` копит батчи в неиспользуемый массив до первого play
  (`SileroBackend.swift:39-44`) — вторая копия книги в памяти.
- **М10.** `headingPause = 0.7` в двух местах, вторая не синхронизируется
  (`AVSpeechBackend.swift:140`, `SileroBackend.swift:19`).
- **М11.** `SleepTimer`: дрейф от сложения `Task.sleep(1s)` + сильный захват self
  (`SleepTimer.swift:14-28`).
- **М12.** `ObjectIdentifier`-ключи utterances: теоретический ложный `.didStart` после
  переиспользования адреса (`AVSpeechBackend.swift:25,142,153,162`) — подозреваемое.
- **М13.** `SettingsStore` не `@MainActor` при мутациях `@Published` из Task.
- **М14.** `EncodedSentence` не хранит `charOffset` (`SentencePageCache.swift:13-41`) — добавить
  сейчас (обратно совместимо), иначе кэш reflow (П9) молча сломает подсветку.
- **М15.** Хит-тест тапа в reflow — O(предложений) с NSString-бриджингом каждого
  (`ReflowReaderView.swift:592-607`); предрассчитать `[NSRange]` + бинарный поиск.

### Сервер, мелочи

- `secrets.compare_digest` падает 500 на не-ASCII заголовке (`server.py:40`) — сравнивать байты.
- Нет кэша повторных фраз (LRU по `sha1(text|speaker)` снял бы и часть нагрузки С3).
- `print` буферизуется под systemd — `PYTHONUNBUFFERED=1` в юнит (иначе лог ошибки С1 не виден).
- Юнит: дефолт `Environment=WORKERS=1` перед `EnvironmentFile`, `MemoryMax`, `network-online.target`,
  `StartLimitIntervalSec`.
- `requirements.txt` без пинов и не участвует в прод-деплое (`DEPLOY.md` ставит ручным списком) —
  запинить и сделать единственным источником.
- Возможный щелчок: `(audio*32767).astype(int16)` без `np.clip` (`server.py:82`).
- `benchmark.py`: вердикт «✅» игнорирует ошибки; нет p95.
- Расхождения `DEPLOY.md`: CAX21 vs `WORKERS=1`; «ключ в Настройках» устарел; CX23 vs CAX21 в CLAUDE.md.
- `asyncio.get_event_loop()` → `get_running_loop()`.

## Проверено и НЕ является багом

- Карта смещений `TextPipeline.cleanPage` → NSRange (переносы, junk в середине, суррогатные пары) —
  корректна (харнесс).

- Reflow-подсветка (flatten ↔ globalRange) — расхождений нет.
- Ключи кэша (`UUID.ext`) — коллизии невозможны.
- Инъекций в логи сервера нет; секретов в git самого silero-server нет (единственный утёкший
  секрет — К2 в Swift-коде).
